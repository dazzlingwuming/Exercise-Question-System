# 从一道题到下一次复习

2026-10-29，第二轮改进。接续 [图片与图解改造](multimodal-learning.md)，所有功能仍放在原有首页、练习和题目输入流程中。本轮未增加应用依赖或数据库表结构。

## 研究后采用的方向

查阅的是产品官方介绍和使用手册。借鉴交互与学习组织方式，不把它们的效果宣传视为本项目的效果验证。

| 参考 | 对本项目的启发 | 本轮实现 |
| --- | --- | --- |
| [Anki 学习手册](https://docs.ankiweb.net/manual/studying)区分新题、学习中、到期复习，并在回忆后反馈掌握情况 | 每次打开应用应知道先学什么；答对以后仍然需要复习 | 今日小批次、到期数量、下次复习时间、持续复习安排 |
| [NotebookLM 官方学习功能介绍](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-student-features/)把测验、解释和来源关联 | 练完需要有具体后续动作，复盘应基于这次实际作答 | 本轮报告、薄弱知识点、继续未答题、完成自评、仅重练薄弱题 |
| [Khanmigo 学习者介绍](https://www.khanmigo.ai/learners)强调通过提问引导学生思考 | 助手应能检查过程，并给学生继续思考的机会 | 检查我的步骤、问我一个问题，保留已有图片与文字输入 |

## 使用方式

1. **首页选每日目标**：5、10、20 题。显示今天已练的不同题目数和到期复习数量；点击开始后题目顺序固定。先放到期题，再放错题/部分掌握题，最后补新题。不为凑数混入已掌握且未到期的题；不足目标题数时按实际数量练习。
2. **随时接着学**：首页显示上次停在哪一题。未提交草稿保存在同一浏览器的 localStorage，已提交答案从后端按练习会话恢复。关闭标签页、刷新后仍可继续；新一轮练习不会预填旧轮答案。
3. **本轮复盘**：练习中随时打开。分别显示答对、答错/部分掌握、待自评、未作答；逐题跳转，也可只对薄弱题创建新一轮。大列表每次显示 20 项。
4. **图片更容易整理**：录题识别和 AI 对话里的附件支持裁剪，拖动框选或用滑块调整。裁剪生成新图片并替换当前附件，不修改原图资产。题干截图包含答案时，裁去答案后再选择保留到材料中。
5. **按需要选择辅导方式**：输入步骤或上传手写图后，点击“检查我的步骤”；想检验理解时点击“问我一个问题”；原有流程图解释保留，完成的讲解可以复制。

移动端把今日练习放在统计前面，减少寻找入口的滚动。空题库会显示录入第一道题和导入题库的明确入口。“专项突破”先打开筛选配置，不再一点击就用默认条件开练。

## 逻辑与稳定性修正

- 报告只统计当前会话内每题最近一次提交，跳过题不算已答，待自评不算答对。已删除题单独列示，不进入重练队列。
- 主观题较早的作答补做自评时，可以更新历史计数，但不覆盖该题更新的学习状态。重复自评仍保持幂等。
- 连续答对四次后仍安排复习，间隔逐渐延长至最多 90 天。旧数据中没有复习日期的已掌握题，距末次作答超过 14 天后可重新进入复习。沿用简单的规则调度，**不是 FSRS，也没有宣称个性化记忆预测**。
- 学习状态部分迁移时，不把已有作答的题重新当新题；旧记录判断错题使用最近结果，不因更早的错误把已纠正题重新纳入。
- 今日练习量按浏览器时区划定一天，再用 UTC 作答时间查询。同一天重复提交一道题只计一道。
- 切题时原子切换当前题、草稿和作答结果，避免短暂把旧题 attempt 发给新题 AI；无效的题目/作答组合返回可读错误，而不是 500。
- 图片裁剪使用重新获取的图片字节与临时对象 URL，避免已缓存缩略图缺少 CORS 头导致 canvas 失败；对象 URL 离开时释放。图片响应按 Origin 区分缓存。
- 键盘快捷键不干扰按钮、链接、输入框和弹窗；减少动画设置会影响提交后的滚动行为。裁剪支持键盘滑块、焦点循环和 Esc 取消。

## 性能与代码组织

- 今日队列在 SQL 中按优先级筛选并限制题量，不载入完整题库正文。
- 普通练习创建顺序快照时只读取筛选所需元数据，实际进入当前组才读取正文、答案、解析。
- 同一组题的集合路径批量装饰，减少重复读取集合树。
- 多题最新作答查询改用窗口函数批量完成，避免每题查一次数据库。
- 复盘统计不载入全部作答正文与题目快照；恢复答案时才读取对应内容。
- 新增 TodayPlan、SessionReport、ImageCropDialog 和独立的计划/复盘服务，避免把所有新逻辑放进一个页面或路由。

## 验证与边界

- 后端 pytest：175 项通过；前端 Vitest：24 项通过；TypeScript 和生产构建通过。
- 新增覆盖：队列优先级与筛选、会话顺序稳定、最近作答统计、题目快照恢复、已删除题跳过、晚补自评、旧数据兼容、跨时区日期边界、图片聊天保留输入、草稿恢复、切题 AI 上下文隔离。
- 真实浏览器使用独立空数据库和五道合成样题，走通目标设置、作答、刷新恢复、跨页面草稿、复盘、补自评、定向重练、上传与实际裁剪。修复后流程没有接口错误或页面异常。
- 检查桌面 1440px、手机 375/390px、横屏、深色主题、减少动画、放大根字号及裁剪键盘操作。截图在被 Git 忽略的 `output/playwright/` 中。
- 没有调用真实收费模型来评估新增提示的教学效果；步骤检查仍是模型建议，不是数学引擎执行过的证明。没有改动用户实际题库数据，没有提交或推送 GitHub。
- 草稿和目标属于当前浏览器；不提供跨设备同步。裁剪前的原图仍在本地资产库，裁剪不等于从磁盘彻底删除原图。大规模历史会话的报告仍返回轻量条目全集，可在实际规模测试后增加服务端分页。

## 下一步按收益排序

1. **数学工具**：接入明确输入的求值、方程验算、函数作图，展示真实运行结果并区分模型解释。优先支持有限表达式和受约束参数，不执行任意模型代码。
2. **个人复习卡**：从自己确认过的错因和学习摘要提炼要点，关联原题与图片，先回忆再展示解释；避免自动生成大量未经审核的卡片。
3. **图形独立归档**：当前可以裁剪整张附件，下一步可把同一张试卷的题干区、图形区、答案区分别保存并确认对应关系。
4. **按需生成配图**：语文场景与生物过程可接独立图像生成服务，保留预览确认、费用提示及供应商适配。精确几何、函数与实验图优先用程序绘制。
5. **3D 建模**：继续按用户要求排在后面，先让现有学习过程稳定、方便。
