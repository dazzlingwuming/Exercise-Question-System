# 日常学习中的图片与图解

更新：2026-10-29。基于远端 `main` 的 `db5aed9`，保留题库集合、题目版本、练习会话、自评、AI 评分和候选题确认流程。

## 产品方向与本轮交付

图片属于题目、作答和对话的内容，不另设“看图学习”栏目。

| 场景 | 入口与行为 |
| --- | --- |
| 收集截图或试题照片 | 新增题目 → 从文字或图片识别。支持图片单独输入、文字加图片、粘贴、拖放。预览识别结果与缺失字段，再应用到表单。 |
| 题干、材料、解析插图 | 编辑器支持选择、粘贴、拖放图片；预览中可放大。 |
| 手写过程与草稿照片 | 主观题作答编辑器可插图。上传完成后提交；图片随本次作答保存，AI 评分与讲题能收到真实图片。 |
| 随时附图追问 | 原有 AI 学习伙伴输入框添加图片。仅图片也可发送；最近 12 条对话中的用户图片随后续提问重新发送。 |
| 思路图解 | 原有 AI 输入框旁“用流程图解释”。模型返回 Mermaid，前端安全渲染；提交前仍只给提示。 |

原图默认不附到解析草稿，防止含答案的截图直接出现在下一次练习题干中。可明确勾选“将原图保留为题目材料”；几何图、实验图等题目依赖的图形应保留，含答案时先裁剪再上传。不把 AI 推测的答案当成已识别到的标准答案。

本轮没有接入栅格图片生成、3D 建模或真实计算引擎，也没有新建独立的看图页面。AI 自由解题仍是模型推理，不能声称执行过数学验算工具。

## DeepSeek 能力核验

官方当前推荐调用名为 `deepseek-flash`，截至本次核验对应 V4.1 Flash-1017；支持文字和图片输入。本文实现沿用兼容的 Chat Completions 接口，通过 user 消息里的 `image_url` 与 base64 传图。参见 [官方模型调用说明](https://api-docs.deepseek.com/quick_start/agent_integrations/) 和 [图像理解文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)。

图片理解能用于题目转录、图表分析、手写过程讨论；它与图片生成是不同接口能力。本项目的流程图是模型输出图形代码后由 Mermaid 绘制，不是调用一个图片生成模型。

默认讲题模型改为 `deepseek-flash`。官方地址下旧浏览器配置中的 `deepseek-chat` 自动迁移；保留自定义服务商模型名。评分、出题原有 `deepseek-v4-pro` 配置仍保留；含图请求强制选用 `vision_model`，默认 `deepseek-flash`，不能悄悄降级为纯文本请求。

## 实现与边界

- 复用现有图片资产与存储服务，不在聊天数据库中保存 base64。题目和用户消息保存受控资源路径，模型请求时读取并校验原图。
- 新增题目解析接受 `image_ids`，识别失败时的一次 JSON 修复仍携带相同原图和图片模型。
- 对话附件只影响本次对话，不修改原题或历史题目快照。提交后评分读取当时的题目快照，并额外读取本次用户作答中的图片。
- 支持静态 PNG、JPEG、WebP；单张最多 5 MiB、8192 像素边长、1600 万像素。每次完整模型上下文和每道题最多 6 张不同图片、合计 20 MiB；重复引用去重。这个上限包含当前题图、答案图和最近对话附图。
- 图片不可用、不支持看图、超过上限时返回明确错误。上传或模型请求失败后，前端保留可重试的文字与附件。
- 图片、公式与图形识别仍可能出错。模糊字符、缺失条件、缺少答案或评分标准会留给用户核对。
- AI 生成的普通回答继续禁用远程图片加载；Mermaid 保留严格模式、SVG 清理、长度限制和源码降级。
- 含图片的上下文自动生成候选题，仍受原项目限制；本轮未放开此能力。

## 界面与性能整理

采用安静的工作台布局，统一侧边文字导航、顶栏、内容宽度、按钮与面板。移动端使用可关闭的导航窗口，保留键盘导航、命令面板、多主题与专注模式。首页改为学习数据、练习入口和最近记录，去掉持续漂浮背景和跑马灯。

使用用户指定的 [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 与现有 frontend-skill。检索后采用适合工具产品的 Flat Design 指导，保留原品牌和中文系统字体；未采用检索首次返回的儿童风格。

- 页面通过 React.lazy 按需加载；统计图表、编辑器及公式渲染不随首页全部加载。
- RichContent 记忆化，流式增量更新时不重复解析未变化的旧消息。
- 主题令牌拆到 `styles/themes.css`，工作台样式放在 `styles/workspace.css`；删除旧 Dock 和重复样式。
- 提取共用的图片附件组件和 AI 配置表单。
- 首页正确率由 SQL 聚合，不加载所有完整历史答案与题目快照。当前错题统计与错题练习共享状态查询，重复答错只算一道，已纠正的题不会因为历史错误重新计入。
- 错题复习列表仍展示历史错题记录；改为联表查询，去掉逐题查库及重复排序。
- 修复讲题流丢弃独立空格、换行的问题；模型流意外终止或输出被长度上限截断时，不当成完整结果保存。
- 修复 Mermaid 11 顶层 htmlLabels 配置缺失导致的空白节点：禁用 HTML 标签后继续保留 SVG 清理，节点文字可正常显示。

## 后续建议

1. **数学验算与函数作图**：模型负责解释和选择工具；受约束的数学引擎负责求根、求导、代入验算和曲线绘制。优先白名单表达式与明确参数，不直接执行模型生成的任意代码。[Wolfram 官方工具文档](https://reference.wolfram.com/language/ref/LLMTool.html) 展示了这种工具分工。
2. **图形定位与裁剪**：识别时让用户确认“题干区、图形区、答案区”；可把截图中的图形独立保存，降低答案泄露与重复录入。
3. **图片生成适配器**：明确选定服务商后，为语文场景、生物示意等提供“生成配图”动作。返回资产仍走现有图片存储与预览确认；生成插图不能替代精确实验图和标准解答。
4. **大规模与长对话**：按需考虑 Files API、图片引用缓存、窗口管理及错题列表数据库级分页；目前不做没有测量依据的全项目重写。
5. **3D**：按用户要求放在最后，本轮不实施。

学习产品的参考也支持把图像融入辅导会话：[Khan Academy 官方介绍](https://blog.khanacademy.org/whats-new-for-the-2025-26-school-year-big-updates-from-khan-academy-districts/) 描述了在辅导中上传数学、科学题目、手写过程与截图的做法。这为本项目的交互选择提供参考，并不意味着复刻其整套产品。
